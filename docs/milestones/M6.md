# Milestone 6: Attachments, rich text, signatures, templates, drafts and scheduling

**Status:** built. 86 backend tests pass. The rich-text editor was tested in Chromium. The app builds for Android.

## What it does

- **Attachments:**
  - Pick files from the phone and attach them. The server detects the **real file type from the content**: a Windows program renamed `invoice.pdf` is flagged *dangerous*, and the app warns before you send it.
  - Uploads are limited to 25 MB per file. The mailbox's own message-size limit, 25 MB by default, still applies to the whole message, with a clear message if exceeded.
  - Files are never executed or converted on the server.
- **Encrypted file storage:**
  - Every stored file (uploads, cached received attachments, inline images) is encrypted with the **user's own key**. That key is itself encrypted with `CREDENTIAL_KEY`, which isn't in the database.
  - Deleting a user deletes their key, so copies left in backups become unreadable.
  - Identical files of the same user are stored once. Files are never shared between users.
- **Received attachments** are kept as a platform copy the first time they're opened (up to 10 MB each), so they stay available even if the original is deleted from the server.
- **Embedded images in received mail** (`cid:` pictures such as logos) are now shown.
- **The rich-text composer:**
  - Bold, italic, underline, bulleted and numbered lists, three text sizes, links (only `https://`, `http://` and `mailto:`), clear formatting, and pictures inside the text.
  - Pasting always inserts plain text, so no foreign HTML or scripts get into messages.
  - Every message is also sent with a plain-text version.
- **Signatures:** create several and choose one as each mailbox's default. In the composer pick "Mailbox default", "None" or a specific signature. It's added once, above any quoted text.
- **Templates and quick replies:** saved per user and inserted from the composer.
- **Drafts:**
  - Saved automatically on the server every few seconds, so they're on all your devices.
  - If the same draft was changed on another device, you choose **Keep mine as a copy** or **Use the other version**; nothing is overwritten silently.
  - Sending a draft removes it.
- **Forwarding** includes the original attachments; you can switch that off.
- **Scheduled sending:**
  - "Send later…" picks a date and time in your phone's time zone. Times less than a minute away or more than a year ahead are refused.
  - Scheduled messages are listed in the Outbox with **Edit**, which turns the message back into a draft and cancels the send, and **Cancel sending**.
  - The server sends at the scheduled time even if every phone is off.
  - Suspension pauses scheduled messages, as described in M4.
  - Daylight-saving time: the exact moment is stored, so the message goes out at the local time you chose. The phone's picker doesn't offer times that don't exist (spring-forward gap).

## Tests added (8 backend + an editor check in Chromium)

- **Backend:**
  - type detection (a disguised program flagged), encryption on disk (a secret phrase from an uploaded file found nowhere on disk), per-user deduplication;
  - attachment, inline image and signature checked by parsing the sent message like a real email client;
  - the mailbox default signature and "none";
  - forwarding with the original attachments, and embedded images shown in received mail;
  - templates, including duplicate names;
  - drafts across two devices with the conflict refused and the current copy returned, idempotent offline creation, and the draft removed on send;
  - scheduling: too soon refused, nothing sent early, sent when due, and edit-to-draft cancelling the send;
  - another user can't use my uploads, drafts or signatures.
- **Editor (Chromium):** typing, bold and lists at the cursor, `javascript:` links refused, inline image tagging, and pasting an HTML payload with a script arriving as plain text without running.

## Known limitations

- **Files are stored on the server's own disk** (`BLOB_DIR`). That's fine on a VPS. A host with a temporary disk (e.g. Render's free tier) needs the S3-compatible storage driver (`BLOB_DRIVER=s3`, see [M8](M8.md)).
- **Drafts live on the platform only.** They aren't copied into the mailbox's Drafts folder on the mail server.
- **The editor runs in a WebView**, so formatting can look slightly different between Android versions. Recipients' email clients also render HTML differently, which is why a plain-text version is always included.
- **Not yet scanned for viruses** (M9). Only type detection and risk warnings for now.

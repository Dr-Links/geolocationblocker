# Milestone 3: Incoming sync, reading and mailbox actions

**Status:** built and tested against a real IMAP server (Dovecot). 57 backend tests pass. The app builds for Android.

## What it does

- **Background sync that doesn't need the app open.** One cron entry every minute:
  ```
  node dist/cli.js cron
  ```
  It runs the scheduler (expiry, warnings, mailbox retries), then syncs due mailboxes for the rest of the minute and exits. It exits immediately when nothing is due. On a server that allows permanent processes, `node dist/cli.js sync:daemon` does the same continuously.
- **What one pass syncs per mailbox:**
  - INBOX every run, other folders every 5 minutes, and every folder at once when something disappeared (so moves are picked up immediately).
  - New messages from the last 90 days (configurable per mailbox), newest first, 150 per folder per run, so a large mailbox fills in over a few runs.
  - Read/star/answered changes from other email clients. Servers that support CONDSTORE send only what changed.
  - Messages deleted on the server stay readable here and are clearly marked *"Deleted on the server · stored copy"*. The app never pretends they still exist there.
  - Changes in UIDVALIDITY, where the server renumbers a folder, are handled without duplicates.
- **No duplicates:**
  - Messages are identified by the server's stable id when available, otherwise by Message-ID + size.
  - A message in two folders is one message with two locations.
  - Re-running a sync changes nothing.
  - A database lease stops two overlapping runs from syncing the same mailbox.
- **Threads** come from `In-Reply-To`/`References`. A message never joins a conversation because of a similar subject alone. (Conversation views come in M5.)
- **Reading:**
  - The **All inboxes** view combines every mailbox, with a mailbox label on each message, mailbox filter chips, Starred and Unread-only filters.
  - You can also browse each mailbox's folders and their messages.
- **The message view:**
  - Sender, recipients (tap for To/Cc/Reply-to; long-press to copy the sender's address), date, the receiving mailbox and the folder.
  - SPF/DKIM/DMARC results, and a warning when the sender couldn't be verified.
  - HTML is sanitised on the server and shown with JavaScript off and a strict content policy.
  - Remote images (tracking pixels) are blocked until you tap **Show images**.
  - Links open only after you confirm the real destination.
  - Large messages load their text only; attachments are fetched when opened.
  - Attachments show their size and type, risky types get warnings, and they're downloaded and opened through the phone's share sheet.
- **Actions:** mark read/unread (also done automatically when you open a message), star, archive, trash, spam/not spam, move to any folder, and delete forever (only from Trash, with confirmation).
  - Every action goes to the mail server. If it can't be reached, the action shows as *"Syncing change…"* and is applied by the next sync.
  - Sync never overwrites a change that hasn't reached the server yet.
  - After 5 failed attempts the change is undone in the app and recorded as a problem.
  - Sending an action twice (offline retries) applies it only once.
- **The admin** has no database access to messages at all.

## Tests added (10)

All run against a real IMAP server:
- import with bodies, addresses, attachments and sender checks, plus attachment download;
- a message in two folders kept as one;
- replies threaded, while an unrelated message with the same subject isn't;
- the 90-day window;
- idempotent re-runs;
- new mail detection;
- read state, deletions and moves made by another client;
- HTML sanitising (scripts, event handlers, `javascript:` links, styles) and remote-image blocking;
- large messages;
- mark read, star, archive, trash and delete forever, each checked on the server;
- an action kept pending during an outage and applied by the next sync, not overwritten by sync in between;
- duplicate action requests applied once;
- cross-user isolation on every message route;
- overlapping sync runs;
- no syncing for expired accounts.

## Known limitations

- **New mail arrives within about 1–2 minutes** with cron-based sync. Instant delivery (IMAP IDLE) needs a permanent process (`sync:daemon` on a VPS) and is planned with push notifications in M7.
- **Inline images** (embedded `cid:` pictures, e.g. signature logos) show as placeholders. They'll display once attachment storage arrives in M6.
- **No virus scanning yet.** Attachments are labelled "Not scanned for viruses"; scanning is M9.
- **Search, conversation view, sending/replying and notifications** come in M5, M4 and M7.
- **Messages older than the sync window** (90 days by default) aren't imported yet. "Search on server" and a configurable window come with search in M5.

# Milestone 2: Connecting mailboxes

**Status:** built and tested automatically against a real IMAP server (Dovecot) and an SMTP test server. Waiting for your test with real mailboxes once the app is deployed.

## What it does

- **Add mailbox** (app → Home → Add mailbox): enter the address and the mailbox password. The server is found automatically, both incoming (IMAP) and outgoing (SMTP) connections are tested, and only then is the mailbox saved.
- **Automatic discovery**, in this order:
  1. Known providers by address (Gmail, Outlook, Yahoo, iCloud, Zoho, AOL, Fastmail).
  2. The domain's mail (MX) records. This recognises Hostinger Email, Titan, Google Workspace, Microsoft 365, GoDaddy, Namecheap and Zoho on your own domains.
  3. Thunderbird-style autoconfig files, then the Mozilla ISPDB database.
  4. DNS SRV records.
  5. cPanel-style guesses: `mail.<domain>`, the MX host, `imap.<domain>`.

  For outgoing mail, ports 465 (SSL/TLS) and 587 (STARTTLS) are both tried.
- **Manual settings** when discovery fails: host, port, SSL/TLS or STARTTLS, username, and an optional separate outgoing password. The form opens automatically after a failed automatic attempt.
- **Clear errors:** wrong password (with an app-password hint for Gmail and Yahoo), server not found, port closed or blocked, timeout, encryption mismatch, STARTTLS unavailable, and untrusted or mismatched certificates.
- **Certificates are always verified.** If a server's certificate isn't trusted, the app shows who it was issued to, who issued it, its expiry and its fingerprint. On shared hosting it suggests using the certificate's own server name, which is usually the right fix. The user can also trust *that exact certificate*; any other certificate is still rejected. Verification is never simply switched off.
- **Passwords** are encrypted with AES-256-GCM using `CREDENTIAL_KEY`, which is kept outside the database. They are never returned by the API, never logged, and unreadable by the admin's database role.
- **Password changed at the provider:** the first rejected login marks the mailbox **Password needed**. All automatic retries stop, because repeated bad logins can get a mailbox locked by cPanel or Hostinger brute-force protection. The user gets one email and sees the problem in the app. Entering the new password re-tests it and resumes the mailbox.
- **Temporary problems** (server down, timeouts) are retried by the scheduler with backoff: 30 s, 1 min, 2 min … up to 30 min. If the problem continues for about 30 minutes, the user is emailed once.
- **Suspension** pauses all of a user's mailboxes. Reactivation re-verifies them automatically.
- **Disconnect:** *keep stored data* deletes the saved password and stops syncing (stored emails stay readable from M3 on). *Delete* removes the mailbox and all platform data for it. The user must type the address to confirm. The mailbox at the provider is never touched.
- **Admin dashboard:** mailbox health counts and a list of problem mailboxes. Each user's page shows their mailboxes' status, last verification and problems. It never shows passwords, usernames or content.
- **Network safety:** the server refuses to connect to private or internal addresses (loopback, LAN, cloud metadata) and to non-mail ports. It connects to the vetted IP address so a second DNS answer can't redirect it.

## Tests (47 in total, 15 new)

They run against a real Dovecot IMAP server with TLS and an SMTP server, locally and in CI. They cover:
- automatic discovery;
- manual STARTTLS settings;
- **exactly one** login attempt when the password is wrong, counted from the IMAP server's own log;
- duplicates;
- the untrusted-certificate flow, including a tampered certificate being rejected;
- password change → "Password needed" → no automatic retries → new password → resumed;
- an outage with backoff and recovery;
- suspension pausing mailboxes and reactivation resuming them;
- another user getting 404 on every mailbox route;
- the admin role being denied access to credentials;
- disconnect (keep) and delete;
- blocking of private addresses and non-mail ports in production.

## Known limitations

- **Google Workspace / Gmail mailboxes** work with an *app password* only. "Sign in with Google" needs Google's app verification (open question 2 in `docs/08-risks-and-decisions.md`).
- **Microsoft 365 / Outlook mailboxes** can't be connected yet. Microsoft no longer accepts passwords for this, so these need "Sign in with Microsoft" (planned milestone M4b). The app explains this to the user.
- **Not yet tested against real providers** (Hostinger Email, cPanel servers, Zoho…). There's no outbound mail access from this development sandbox. Please test with real mailboxes after deployment.
- **Certificate details** are shown for SSL/TLS ports (993/465). For STARTTLS ports the error is reported without them.

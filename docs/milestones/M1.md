# Milestone 1: Accounts, administrator, approval and one-month access

**Status:** built and tested automatically here. **Waiting for your test on your cPanel hosting and an Android phone.**

## Objective

Users register with a Gmail address, confirm it, and wait. You approve them in the admin dashboard, which starts a one-calendar-month access period in the **user's own time zone**. When the period ends the account is suspended automatically (data kept) until you renew it. You sign in to a separate admin dashboard with a password **and** an authenticator code.

The Gmail address is only the sign-in name. The platform sends it account emails only: confirmation, password reset, approval and expiry notices. Mail from the business mailboxes connected later is **never** sent to it.

### API summary

User API (`https://api.yourdomain`):
`POST /v1/auth/register`, `/resend-verification`, `/verify-email`, `/login`, `/refresh`, `/logout`, `/password-reset/request`, `/password-reset/confirm`; `GET /v1/me`, `PATCH /v1/me` (time zone), `POST /v1/me/password`, `GET /v1/me/sessions`, `DELETE /v1/me/sessions/:id`; `GET /v1/app/home` (needs an active account); email-link pages under `/v1/pages/*`.

Admin API (`https://admin.yourdomain/admin/api`): sign-in + TOTP, dashboard, user list/detail, approve, reject, suspend, renew/reactivate, send password reset, sign out devices, quota, permanent delete (typed email + fresh code), audit log, settings, admin password change, new recovery codes, recovery-email reset, emergency reset.

## Decisions taken in this milestone

- **Hosting: your cPanel account.** Milestone 1 needs only a web app, PostgreSQL and a 1-minute cron job, which cPanel can provide. No extensions or superuser rights are needed. PostgreSQL 13 or newer is required.
- **Time zone:** taken from the phone at registration and kept up to date by the app. The month is calculated in that zone at the moment you approve or renew, and the exact end instant is stored. Example: approved 31 Jan 15:00 Lagos time → ends 28 Feb 15:00 Lagos time.
- **Access is checked on every request**, so an account stops working at the exact second it expires, even if the cron job runs late. Cron then marks it suspended, signs out its devices and sends the emails.
- **Unconfirmed sign-ups are deleted after 7 days**, so nobody can block someone else's Gmail address by registering it first. Resetting the password through the emailed link also counts as confirming the address.

## Setting it up on cPanel

You need: cPanel with **Setup Node.js App** (Node 20.12+; choose 22 if offered), **PostgreSQL Databases** (version 13+), **Terminal** (or SSH), and **Cron Jobs**. If any of these is missing from your cPanel, tell me which one before going further.

### 1. Subdomains and SSL
cPanel → **Domains**: create `api.yourdomain.com` and `admin.yourdomain.com`. Make sure AutoSSL has issued certificates for both (cPanel → **SSL/TLS Status**).

### 2. Database and users
cPanel → **PostgreSQL Databases**:
1. Create database `emailplatform` (cPanel will name it `cpuser_emailplatform`).
2. Create **five** users with different strong passwords: `owner`, `auth`, `api`, `admin`, `worker` (they become `cpuser_owner`, …).
3. Add **each** user to the database.

The migration creates the tables as `owner` and gives the other four users only the rights they need. It **refuses to run** if the users are set up unsafely, for example if one inherits another's rights.

Check the version in **phpPgAdmin** with `SELECT version();`. It must be 13 or newer.

### 3. Get the deployment folder
Either download the `emailplatform-cpanel` artifact from the latest successful **Actions → CI** run of this branch on GitHub, or run `npm ci && npm run package:cpanel` on a computer with Node 22. You get a folder `emailplatform`.

### 4. Create the two Node.js apps
cPanel → **Setup Node.js App** → *Create Application*, twice:

| | API app | Admin app |
|---|---|---|
| Node.js version | 22 (or ≥ 20.12) | same |
| Application mode | Production | Production |
| Application root | `emailplatform-api` | `emailplatform-admin` |
| Application URL | `api.yourdomain.com` | `admin.yourdomain.com` |
| Application startup file | `api.cjs` | `admin.cjs` |
| Environment variable | `ENV_FILE` = `/home/CPUSER/emailplatform.env` | same |

Upload the **contents** of the `emailplatform` folder into **both** application roots (File Manager → upload the zip → Extract). In each app press **Run NPM Install**.

### 5. Keys and settings
In **Terminal** (copy the "enter virtual environment" command shown at the top of the API app's page first):
```bash
cd ~/emailplatform-api
mkdir -p ~/secrets && chmod 700 ~/secrets
node dist/cli.js keys:generate
```
- Save the `CREDENTIAL_KEY=` value (just the part after `=`) in `~/secrets/credential_key`.
- Save the PEM block (from `-----BEGIN PRIVATE KEY-----` through `-----END PRIVATE KEY-----`) in `~/secrets/jwt_ed25519.pem`.
- Save the password of the mailbox that sends account emails (e.g. `no-reply@yourdomain.com`, created in cPanel → **Email Accounts**) in `~/secrets/smtp_password`.
- Then run `chmod 600 ~/secrets/*`.

Copy `env.example` to `/home/CPUSER/emailplatform.env`, fill in every value, then `chmod 600 ~/emailplatform.env`. **Back up the two key files somewhere offline.** If you lose `credential_key`, the admin authenticator (and, from M2, all mailbox passwords) will have to be set up again.

### 6. Database tables and your administrator account
```bash
cd ~/emailplatform-api
node dist/cli.js db:migrate
node dist/cli.js admin:create --email you@yourdomain.com
```
`admin:create` asks for a password (14+ characters). It then prints an **authenticator key** (add it to Google Authenticator, Microsoft Authenticator, Aegis…) and **10 recovery codes**. Store the codes offline; they are shown only once.

Then restart both apps in Setup Node.js App.

### 7. Cron job
cPanel → **Cron Jobs**, *Every minute* (`* * * * *`):
```
cd /home/CPUSER/emailplatform-api && ENV_FILE=/home/CPUSER/emailplatform.env /home/CPUSER/nodevenv/emailplatform-api/22/bin/node dist/cli.js scheduler:tick >> /home/CPUSER/emailplatform-scheduler.log 2>&1
```
Adjust `22` to the Node version you chose. The exact `nodevenv` path is shown on the app's page. If your host does not allow every minute, use its shortest interval. Expiry is still enforced on time, because every request checks it; cron only sends the emails and tidies up.

### 8. Email deliverability
cPanel → **Email Deliverability**: make sure SPF and DKIM are valid for the sending domain. Otherwise Gmail may put confirmation emails in Spam.

### 9. Milestone 2 prerequisite (please run and send me the output)
```bash
cd ~/emailplatform-api && node dist/cli.js check:outbound --host mail.one-of-your-domains.com
```
This shows whether your hosting lets the platform connect to external mail servers (ports 993/465/587). Shared hosting often blocks these, and mailbox sync in M2 depends on them.

## Installing the Android app

Choose one:
- **Quickest (Expo Go):** on a computer with Node 22, run `cd apps/mobile && npm ci && EXPO_PUBLIC_API_URL=https://api.yourdomain.com npx expo start`. Scan the QR code with the **Expo Go** app (it must support SDK 58).
- **Installable APK (no computer setup):** create a free Expo account, set `EXPO_PUBLIC_API_URL` in `apps/mobile/eas.json` (profile `preview`), then run `cd apps/mobile && npx eas-cli@latest build -p android --profile preview`. Download the APK from the link it prints.

## Test checklist (what to do → what you should see)

1. Open `https://admin.yourdomain.com` → sign-in page. Password, then the 6-digit code → dashboard.
2. In the app: **Create account** with a non-Gmail address → "Please use a Gmail address". With your Gmail → "Confirm your Gmail address" screen.
3. Gmail inbox → "Confirm your email address" → button → page says "waiting for approval". You (admin address) get "New registration pending approval".
4. Sign in on the app → **Waiting for approval** screen. "Check again" keeps you there.
5. Admin → Users → Pending → the user → add a payment note → **Approve**. The user gets an "approved" email that shows the end date in their time zone. In the app, "Check again" → home screen with "Active until …".
6. Admin → **Suspend** → the app signs out at its next request. Signing in shows **Account suspended**. Admin → **Reactivate** → works again.
7. Expiry test (Terminal): `psql -h localhost -U cpuser_owner cpuser_emailplatform -c "UPDATE app.users SET access_expires_at = now() + interval '2 minutes' WHERE email_display = 'you@gmail.com'"`. Within 2 minutes the app shows **Your access period has ended**, and after the next cron run both you and the user get emails. Renew from the admin page.
8. App → **Forgot password?** → reset email → new password. Old sessions are signed out.
9. App → **Signed-in devices** → sign out another device.
10. Admin → **Audit log** lists everything above. Admin → user → **Permanently delete** asks for the typed email and a code.
11. Admin → Settings → set a **recovery email** (ideally not on this server). Sign out, then use **Forgot password?** on the admin sign-in page.
12. Emergency recovery: `node dist/cli.js admin:emergency-reset` prints a 15-minute link. Opening it lets you set a new password and authenticator.

## Known limitations of Milestone 1

- **Not yet run on your actual cPanel server or on a real phone.** I have no access to either. Passenger and PostgreSQL versions differ between hosts; report any errors from the app's log (`stderr.log` in the application root).
- **Account emails are sent once, without retry.** If your mail server is down at that moment, the user can press "Send the link again" or "Forgot password?". The admin sees a failure when sending a reset link. Retrying with a queue arrives with the job system in M2.
- **Per-IP request limits are kept in memory per process.** Login throttling, the important protection, is stored in the database and always applies.
- **No push notifications, mailboxes, quotas in use, or backups yet** (later milestones). Quotas can already be set, but nothing consumes storage yet.
- **The app's minimum-version check exists on the server** (`MIN_APP_VERSION`), but the "please update" screen is not wired into the app yet.
- **cPanel's Node.js app (Passenger) stops idle apps.** The first request after a quiet period can take a few seconds.

# Milestone 5: Conversations and search

**Status:** built and tested against the IMAP test server. 78 backend tests pass. The app builds for Android.

## What it does

- **Conversation view** (the default in All inboxes; tap the chip to switch to single messages):
  - One row per conversation, showing participants, message count, unread state, star, attachments and the mailbox(es) involved.
  - A conversation can span several of your mailboxes (e.g. a customer wrote to `sales@` and the reply came to `support@`). Every message is labelled with the mailbox that holds it.
  - Filtering by one mailbox still shows its conversations.
- **How conversations are formed:**
  1. `In-Reply-To` / `References` headers, in either arrival order.
  2. If a later message links two existing conversations, they are merged.
  3. A narrow subject fallback only for messages that are clearly replies (`Re:`, `Fwd:` …) whose original is missing: it also needs the same correspondent (your own addresses don't count) and a date within 14 days.

  Unrelated mail with the same subject never merges. This is tested, including a stranger's "Re: Invoice 77".
- **Search across all mailboxes,** Sent included. Each result shows the mailbox it belongs to.
  - **Words** match subject, sender/recipients, body text and attachment names. Words match from their start ("quot" finds "quotation"), and all words must match.
  - **Filters:** from (name or address), to, subject, received date range, mailbox, folder (inbox/sent/archive/spam/trash), unread, starred, has attachments. Filters combine.
  - **Saved searches** per user (tap to run, long-press to delete).
  - **"Search older mail on the server"** searches the mail server directly for messages outside the sync window (90 days by default). It adds up to 30 matches per mailbox, so they can be found and opened afterwards.
- **Safety:** search input is turned into a safe query (no query-syntax or SQL injection; tested). Results are always limited to your own mail by the database.

`migrations/0005_search.sql`, `src/routes/{threads,search}.ts`, threading in `src/sync/store.ts`. App: `src/components/ThreadList.tsx`, `src/app/(app)/{thread/[id],search}.tsx`, conversation toggle in `inbox.tsx`.

API: `GET /v1/threads?view=inbox|sent|flagged|folder`, `GET /v1/threads/:id`, `GET /v1/search?q=&from=&to=&subject=&mailboxId=&in=&unread=&flagged=&hasAttachments=&dateFrom=&dateTo=`, `GET|POST /v1/saved-searches`, `DELETE /v1/saved-searches/:id`, `POST /v1/mailboxes/:id/server-search`.

## Bugs found and fixed by these tests

- Two mailboxes syncing at the same moment could split one conversation in two. Conversation assignment is now serialised per user.
- The subject fallback counted your own address as a "shared participant". It no longer does.
- Server search could deadlock the IMAP connection. Results are now read before bodies are fetched.

## How search works, and its limits

- It uses PostgreSQL full-text search with the language-neutral `simple` configuration: no stemming, so "invoices" doesn't find "invoice" (but "invoice" finds "invoices" by prefix). It works for any language.
- Only mail stored on the platform is searched. That's the sync window plus anything imported by server search.
- Messages whose body isn't stored yet match on subject, addresses and attachment names until the body is fetched.
- The search index takes roughly 20–40% of the stored text size. It isn't counted in the user's quota but is monitored as server storage (M8).

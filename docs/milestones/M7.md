# Milestone 7: Push notifications, offline use and multi-device sync

**Status:** built. 93 backend tests pass, including 7 new tests for push and the change feed. The app typechecks and builds for Android.

**Not yet tested on a real phone.** Real push delivery needs an EAS project ID and a development build (see "What you need to do"). Offline behaviour has so far been checked only with typechecking and the tests; you check it on a phone in airplane mode.

## What it does

- **Push notifications** when new mail arrives, sent by the backend even while the app is closed:
  - The text is only **"New email received at sales@company.com"**. The sender, subject and contents are never in a notification, not even in its hidden data, which holds ids only. A test checks this.
  - If more than 5 arrive at once for one mailbox, they're collapsed into one: "6 new emails received at …".
  - A mailbox's first sync never notifies, so connecting a mailbox with 10,000 old emails doesn't flood the phone.
  - Other notices: "A message from … could not be sent", and a notice when a mailbox needs attention (for example a new password). Follow-up reminders get their notices in M9.
  - Each notification is sent once per phone, however often sync runs.
  - Tapping a notification opens the right inbox, or the outbox for send problems.
- **Notification settings:** switch each kind on or off, and new-mail notices per mailbox (*Home → Notifications*).
- **Devices:**
  - Signing out removes the phone's push token, so a signed-out phone gets nothing.
  - A phone reused for another account stops getting the first account's notifications.
  - Tokens the push service reports as dead are switched off automatically.
- **Offline use:**
  - Mail lists, conversations and opened messages are saved on the phone in an **encrypted database** (SQLCipher). Its key is in the phone's secure storage (Android Keystore).
  - Without a connection, the app shows the saved copy with an "Offline" banner.
  - Read/unread, flag, move, delete and the other message actions done offline are queued and applied once when back online. Each carries an operation id, so it can never be applied twice.
  - Messages sent offline wait in **"Waiting on this phone"** in the Outbox and are sent when back online. They reuse the same idempotency key, so a message can't go out twice even if the connection drops mid-way. The app says clearly that the message **has not been sent yet**.
  - If the server refuses a queued item (for example the account was suspended), it's shown with the reason and can be removed.
  - Signing out erases the phone's saved mail and queue.
- **Multi-device:**
  - Every change to messages, drafts, the outbox and mailboxes is recorded in a per-user change feed.
  - Open apps check it every 30 s, and when the app comes to the foreground, then reload what changed. A message read on the tablet shows as read on the phone.
  - Drafts already have versions from M6, so the second device to save gets a conflict instead of silently overwriting.

## Push provider setup

The backend uses the **Expo push service** by default. It delivers to Android (through FCM) and iOS (through APNs) with one kind of token.

| Setting (env file) | Meaning |
|---|---|
| `PUSH_PROVIDER` | `expo` (default), `fcm`, or `none` |
| `EXPO_ACCESS_TOKEN` | optional; set it if you turn on "enhanced push security" in your Expo account |
| `FCM_SERVICE_ACCOUNT` | only for `fcm`: the Firebase service-account JSON, as one line. **Put it in the env file or GitHub Secrets, never in chat.** |

Notifications go out at the end of each `cron` run, or within a few seconds if `sync:daemon` is running.

## What you need to do

1. Create a free Expo account and run `npx eas init` in `apps/mobile`. This writes `extra.eas.projectId` into `app.json`.
2. For Android, add the Firebase `google-services.json` to EAS credentials. This is needed for FCM delivery, even through Expo.
3. Build a development or preview APK: `npx eas build -p android --profile preview`.
4. Test:
   - Sign in, allow notifications, close the app, and send mail to a connected mailbox. Within a cron interval you should get "New email received at …".
   - Turn on airplane mode: open saved messages, flag one, write a reply and send it. Check that it shows under "Waiting on this phone".
   - Turn airplane mode off: the reply is sent once, and the flag appears on webmail.
   - Sign in on two phones, read a message on one, and watch it turn read on the other.

## Known limitations

- Offline compose works for new messages and replies without new attachments. Picking a file needs a connection, because files are uploaded straight away.
- The local cache holds what you've opened or listed recently. It isn't a full offline copy of every mailbox.
- iOS push needs an Apple developer account (APNs key in EAS). The code is ready, but it hasn't been tested on iOS.
- Without the EAS project ID the app still works, but registering for push reports "not available in this build".
